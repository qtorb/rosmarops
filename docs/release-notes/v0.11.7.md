# RosmarOps v0.11.7

v0.11.7 measures your agents' settings more accurately. Your score may change after updating, up or down. Update if you use 0.11.6 or an earlier version.
- Claude Code in «auto» mode and Cursor with Auto-review: when they use a known MCP service (payments, code, email…) and no rule covers it, the report now says another AI model decides, not that they ask you. That is what their documentation says. Your score can go down: a payment service now shows in red.
- Claude Code's sandbox and Grok Build's sandbox profile now count on macOS, Linux and WSL2. On Windows they do not exist, so nothing changes there. Claude Code's sandbox only counts with `failIfUnavailable`: without it, commands run outside the sandbox when it cannot start.
- A Claude Code `deny` rule for reading a file now also blocks the usual terminal commands, like `cat` or `head`. A program the agent launches can still read the file on its own, unless a sandbox is active.
- `Bash(curl *)` or `Bash(wget *)` in Claude Code's allow list now count as a way to send data out.
- Each project now starts with its own Claude Code mode, as it does in the terminal. If the Claude Code extension for VS Code is installed, RosmarOps takes the less restrictive of the project's mode and yours, because the extension does not use the project's.
- `~/.claude/settings.local.json` now counts only when your home folder is itself a project, as Claude Code's documentation says.
- When you mark findings with `rosmarops findings`, RosmarOps now writes only inside `~/.rosmarops`. If your settings come from another file, it tells you and does not change that file.
- Counts with one item now read correctly in more places, for example «1 project in 1 folder».

## Which file to download
- Windows: `rosmarops.exe`
- Mac with Apple silicon (M1, M2, M3, M4): `rosmarops-macos-apple-silicon`
- Mac with Intel: `rosmarops-macos-intel`
- Linux and WSL, x86-64: `rosmarops-linux-amd64`
- Linux on ARM (for example a Raspberry Pi or an ARM server): `rosmarops-linux-arm64`
- `sample-report.en.html` and `sample-report.es.html`: a sample report made by this version on an invented computer. You do not need them to run RosmarOps.

Not sure which Mac you have? Apple menu > About This Mac: «Chip» means Apple silicon, «Processor» means Intel. `SHA256SUMS.txt` is only for checking the download, and you do not need «Source code» to run RosmarOps. On Linux, make it executable first with `chmod +x rosmarops-linux-amd64`, then run `./rosmarops-linux-amd64`.

# RosmarOps v0.11.7 (español)

La v0.11.7 mide con más exactitud los ajustes de tus agentes. Tu nota puede cambiar al actualizar, hacia arriba o hacia abajo. Actualiza si usas la 0.11.6 o una versión anterior.
- Claude Code en modo «auto» y Cursor con Auto-review: cuando usan un servicio MCP conocido (pagos, código, correo…) y ninguna regla lo cubre, el informe dice ahora que decide otro modelo de IA, no que te preguntan. Es lo que dice su documentación. Tu nota puede bajar: un servicio de pago sale ahora en rojo.
- El sandbox de Claude Code y el perfil de sandbox de Grok Build cuentan ahora en macOS, Linux y WSL2. En Windows no existen, así que ahí no cambia nada. El sandbox de Claude Code solo cuenta con `failIfUnavailable`: sin él, las órdenes se ejecutan fuera del sandbox si este no puede arrancar.
- Una regla `deny` de Claude Code para leer un fichero bloquea ahora también las órdenes habituales de la terminal, como `cat` o `head`. Un programa que lance el agente puede seguir leyendo el fichero por su cuenta, salvo con un sandbox activo.
- `Bash(curl *)` o `Bash(wget *)` en la lista de permitidos de Claude Code cuentan ahora como una forma de enviar datos fuera.
- Cada proyecto arranca ahora con su propio modo de Claude Code, como pasa en la terminal. Si tienes instalada la extensión de Claude Code para VS Code, RosmarOps toma el menos restrictivo entre el modo del proyecto y el tuyo, porque la extensión no usa el del proyecto.
- `~/.claude/settings.local.json` cuenta ahora solo cuando tu carpeta personal es un proyecto, como dice la documentación de Claude Code.
- Cuando marcas avisos con `rosmarops findings`, RosmarOps escribe ahora solo dentro de `~/.rosmarops`. Si tu configuración viene de otro fichero, te lo dice y no cambia ese fichero.
- Los recuentos de un solo elemento se leen bien en más sitios, por ejemplo «1 proyecto en 1 carpeta».
