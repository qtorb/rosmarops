# RosmarOps v0.21.0

v0.21.0 is about a first review that ends, and a report that says what it could not finish.
- Large projects finish: the search for keys in files and in git history is much faster and finds exactly the same. On our test computer, with one processor core, three very large repositories that used to be cut off at the minute now finish.
- If a project is not finished, the report says so: «What we could not read» now starts with the projects that went over their minute, by path, with what that means and what to do. What RosmarOps found in them before the cut is in the report; what was left to check is not. The count on the «Findings» line links there.
- No more internal codes: each source RosmarOps could not read now says why in words, for example "not opened: it is larger than 2 MB".
- Cancelling is not a failure: if you press Ctrl+C or close the window while RosmarOps is working, it stops, says "Review cancelled. The previous report has not changed." and does not list it as a problem next time.
- One line less: a problem with a single finding no longer repeats its title.
- Hermes Agent in a container: RosmarOps now counts that its memory and its skills are still written on your computer. If you use Hermes this way, your score can go down without you having changed anything.
- Claude Code's own memory: in manual mode, Claude Code writes its automatic memory without asking, and RosmarOps now counts it. It also reads whether that memory is turned off, and where it is kept, in every settings file.
- Your score can change: Hermes in a container with memory and a skill that has a script goes from 100 to 39 on our test computer; with memory only, to 77. Claude Code in manual mode with memory goes from 74 to 73. No factory score changes. The index stays at version 7.
- A corrected promise: the problem list used to say we could see where a review stopped. What you send does not say that; the text now says what we do learn: that it happened, and on which version and system.

## Which file to download
- Windows: `rosmarops.exe`
- Mac with Apple silicon (M1, M2, M3, M4): `rosmarops-macos-apple-silicon`
- Mac with Intel: `rosmarops-macos-intel`
- Linux and WSL, x86-64: `rosmarops-linux-amd64`
- Linux on ARM (for example a Raspberry Pi or an ARM server): `rosmarops-linux-arm64`
- `sample-report.en.html` and `sample-report.es.html`: a sample report made by this version on an invented computer. You do not need them to run RosmarOps.

Not sure which Mac you have? Apple menu > About This Mac: «Chip» means Apple silicon, «Processor» means Intel. `SHA256SUMS.txt` is only for checking the download, and you do not need «Source code» to run RosmarOps. On Linux, make it executable first with `chmod +x rosmarops-linux-amd64`, then run `./rosmarops-linux-amd64`.

# RosmarOps v0.21.0 (español)

La v0.21.0 va de que la primera revisión termine, y de un informe que dice lo que no pudo acabar.
- Los proyectos grandes terminan: la búsqueda de claves en los ficheros y en el historial de git es mucho más rápida y encuentra exactamente lo mismo. En nuestro ordenador de pruebas, con un solo núcleo, tres repositorios muy grandes que antes se cortaban al minuto ahora terminan.
- Si un proyecto no termina, el informe lo dice: «Lo que no pudimos leer» empieza ahora por los proyectos que pasaron de su minuto, con su ruta, qué significa y qué hacer. Lo que RosmarOps encontró en ellos antes del corte está en el informe; lo que le faltaba por mirar, no. El recuento de la línea de «Avisos» lleva hasta ahí.
- Se acabaron los códigos internos: cada fuente que RosmarOps no pudo leer dice ahora por qué con palabras, por ejemplo «no se abrió: pesa más de 2 MB».
- Cancelar no es un fallo: si pulsas Ctrl+C o cierras la ventana mientras RosmarOps trabaja, para, dice «Revisión cancelada. El informe anterior no ha cambiado.» y no lo apunta como un problema la vez siguiente.
- Una línea menos: un problema con un solo aviso ya no repite su título.
- Hermes Agent en un contenedor: RosmarOps cuenta ahora que su memoria y sus skills se siguen escribiendo en tu ordenador. Si usas Hermes así, tu nota puede bajar sin que hayas cambiado nada.
- La memoria de Claude Code: en modo manual, Claude Code escribe su memoria automática sin preguntar, y RosmarOps ahora lo cuenta. También lee si esa memoria está apagada, y dónde se guarda, en todos los ficheros de ajustes.
- Tu nota puede cambiar: Hermes en un contenedor, con memoria y una skill con script, pasa de 100 a 39 en nuestro ordenador de pruebas; solo con memoria, a 77. Claude Code en modo manual con memoria pasa de 74 a 73. No cambia ninguna nota de fábrica. El índice sigue en la versión 7.
- Una promesa corregida: la lista de problemas decía que podríamos ver dónde se paró una revisión. Lo que envías no lo dice; el texto dice ahora lo que sí sabemos: que pasó, y en qué versión y sistema.
