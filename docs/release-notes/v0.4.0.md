# RosmarOps v0.4.0

Where your MCP servers send data, and harder to fool. Windows only.

## What's new
- Records where each MCP server sends data: the domain of a remote server, or the program behind a local one. The report names it when a server is new.
- Warns when an MCP server points somewhere else since the last run: a new address, program or arguments, a changed setting that isn't a secret, or an edited local script. Rotating a key doesn't count as a change.
- Reads the `headers` of MCP servers in Cursor, Cline and Claude Desktop as credentials, and the MCP servers in Claude Code's `managed-mcp.json`.
- An MCP server you accepted in your allow list stops being accepted if it starts pointing somewhere else.
- Harder to fool:
  - a setting written with unexpected capital letters is a red finding, because the agent and RosmarOps could be reading different values;
  - a source RosmarOps couldn't read never leaves the report green;
  - text read from your files is cleaned before it reaches the report and the «Copy for your AI» text, and that text tells your AI to treat paths and names as data;
  - if RosmarOps's memory of past findings is missing, the report says so instead of calling it a first run;
  - the report counts the warnings your configuration hides (allow list and keys marked as rotated), and the Markdown report lists them.
- The warning that your weekly review task changed now also appears in Spanish, and in the report's list of other signals.

Everything in v0.3.0 is still there.

## Install
Download `rosmarops.exe` and double-click it. If you used an earlier version, RosmarOps asks you to confirm the new version the first time.

## Check the download
```
gh attestation verify rosmarops.exe --repo qtorb/rosmarops
```
Compare the SHA-256 with `SHA256SUMS.txt`. Building this tag from a clean git clone with Go 1.24.7 (`GOTOOLCHAIN=go1.24.7 CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags="-X main.version=0.4.0" -o rosmarops.exe ./cmd/rosmarops`) gives the same `rosmarops.exe`.

## Known limits
- A server started from a package that is downloaded on every run (such as `npx package@latest`) can change at its source without anything changing on your disk. RosmarOps doesn't see that, because it has no network access.
- The first run of this version has nothing to compare destinations with, so it reports no destination changes.
- MCP allow-list entries you already have are tied to the destination their server has at the first run of this version.
- Anyone who can already write files as your user can also rewrite RosmarOps's memory.
- The limits of v0.3.0 still apply.

See `docs/trust-model.md` for every claim and how to check it.
