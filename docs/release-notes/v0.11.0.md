# RosmarOps v0.11.0

v0.11.0 lets RosmarOps tell us when something goes wrong on your computer, only if you say so. Update if you use 0.10.3 or an earlier version.
- When RosmarOps runs into a problem, it notes it on your computer and asks you whether to send it. For example, a step that fails, a check that runs out of time or a report that doesn't open. It sends it only if you press «Send».
- What it sends: error codes, the part of the check, the agent involved, the version, the system, the language and the day. Never your files, paths, user or computer names, keys or settings. You can see the exact text before sending it, and add a comment or your email if you want an answer.
- You can tick «Send the next ones without asking». To be asked again, press «Ask me before sending» in the next notice, or run `rosmarops problems ask`.
- In scheduled checks, with nobody in front of the computer, it never asks. It only sends if you ticked that box; otherwise it waits for the next time you open RosmarOps.
- Every send is listed in rosmarops-sends.log, next to your space's sends. If you block app.rosmarops.com, everything else works the same.
- The trust model changes one line: «It never sends telemetry» becomes «It never sends anything you haven't approved». The tests that prove it are in `tests/trust`.
- Two findings appeared in English in the Spanish report: «A project makes … run one of its own scripts» and «… is a known malicious release». They are now translated.
- The README now lists the nine agents RosmarOps scores and explains how to install it on Linux.

## Which file to download
- Windows: `rosmarops.exe`
- Mac with Apple silicon (M1, M2, M3, M4): `rosmarops-macos-apple-silicon`
- Mac with Intel: `rosmarops-macos-intel`
- Linux and WSL, x86-64: `rosmarops-linux-amd64`
- Linux on ARM (for example a Raspberry Pi or an ARM server): `rosmarops-linux-arm64`
- `sample-report.en.html` and `sample-report.es.html`: a sample report made by this version on an invented computer. You do not need them to run RosmarOps.

Not sure which Mac you have? Apple menu > About This Mac: «Chip» means Apple silicon, «Processor» means Intel. `SHA256SUMS.txt` is only for checking the download, and you do not need «Source code» to run RosmarOps. On Linux, make it executable first with `chmod +x rosmarops-linux-amd64`, then run `./rosmarops-linux-amd64`.

# RosmarOps v0.11.0 (español)

La v0.11.0 permite que RosmarOps nos avise cuando algo falla en tu ordenador, solo si tú quieres. Actualiza si usas la 0.10.3 o una versión anterior.
- Cuando RosmarOps encuentra un problema, lo anota en tu ordenador y te pregunta si quieres enviarlo. Por ejemplo, un paso que falla, una revisión que se queda sin tiempo o un informe que no se abre. Solo lo envía si pulsas «Enviar».
- Lo que envía: códigos de error, la parte de la revisión, el agente afectado, la versión, el sistema, el idioma y el día. Nunca tus ficheros, rutas, nombres de usuario o de ordenador, claves ni configuración. Puedes ver el texto exacto antes de enviarlo y añadir un comentario o tu correo si quieres respuesta.
- Puedes marcar «Enviar los próximos sin preguntarme». Para que vuelva a preguntarte, pulsa «Pregúntame antes de enviar» en el siguiente aviso, o ejecuta `rosmarops problems ask`.
- En las revisiones programadas, sin nadie delante del ordenador, nunca pregunta. Solo envía si marcaste esa casilla; si no, espera a la próxima vez que abras RosmarOps.
- Cada envío queda en rosmarops-sends.log, junto a los de tu espacio. Si bloqueas app.rosmarops.com, todo lo demás funciona igual.
- El modelo de confianza cambia una línea: «It never sends telemetry» pasa a «It never sends anything you haven't approved». Los tests que lo prueban están en `tests/trust`.
- Dos avisos salían en inglés en el informe en español: «Un proyecto hace que … ejecute uno de sus propios scripts» y «… es una versión maliciosa conocida». Ahora están traducidos.
- El README dice ahora los nueve agentes que puntúa RosmarOps y cómo instalarlo en Linux.
