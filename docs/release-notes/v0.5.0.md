# RosmarOps v0.5.0

Skills, Hermes Agent, known malicious packages, and a first preview for macOS.

## What's new
- macOS preview: `rosmarops-darwin-arm64` (Apple silicon) and `rosmarops-darwin-amd64` (Intel), built and checked like the Windows program. The report opens in your browser and lists what the preview does not check yet on macOS; none of that counts as clean. Not signed or notarised by Apple: see the README for the `xattr` step.
- Reads agent skills. A skill's `SKILL.md` counts as instructions and the files in its `scripts` folder as programs the agent runs, for Claude Code, Cursor, Codex, Antigravity, Hermes Agent and Cline. A skill in a shared `.agents\skills` folder is attributed to every agent that loads it, including skills installed with links by `npx skills add`. The report tells you when one agent can change a skill another agent runs.
- Hermes Agent: reads its MCP servers and its approval mode from `config.yaml` (when the mode is not set, Hermes uses `smart`: another AI model approves risky commands), its key files (`.env`, `auth.json`) and its skills, including the ones it ships in category folders. Hermes is detected but not scored yet.
- Codex: reads its key files.
- Known malicious packages: RosmarOps carries a snapshot of threat data and checks it on your computer, with nothing sent anywhere. It looks at MCP servers started with a pinned package version, Python packages installed for your user and in each project's `.venv` or `venv`, and global npm packages. The first entry is LiteLLM 1.107.0. The report shows the date of the threat data at the bottom: no match means no information, not a clean result.
- A source RosmarOps could not read only takes away the score of the agent it belongs to. The report still turns at least yellow and lists it.
- Slow repositories no longer stop the other checks: the repository scan now runs last.
- When one agent can change a program another agent runs, the finding says so, instead of repeating the configuration title.

Everything in v0.4.0 is still there.

## Install
Windows: download `rosmarops.exe` and double-click it. If you used an earlier version, RosmarOps asks you to confirm the new version the first time.

macOS (preview): follow «Install and run (macOS, preview)» in the README.

## Check the download
```
gh attestation verify rosmarops.exe --repo qtorb/rosmarops
gh attestation verify rosmarops-darwin-arm64 --repo qtorb/rosmarops
shasum -a 256 -c --ignore-missing SHA256SUMS.txt
```
Building this tag from a clean git clone with Go 1.24.7 (`GOTOOLCHAIN=go1.24.7 CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags="-X main.version=0.5.0" -o rosmarops.exe ./cmd/rosmarops`) gives the same `rosmarops.exe`; for macOS, the same with `GOOS=darwin GOARCH=arm64` or `GOARCH=amd64`.

## Known limits
- On a computer with many large repositories, or several copies of the same one, the repository scan can still reach the time limit. The other checks finish, and the report says which part was cut.
- The threat data is as recent as this version. Exact versions only: a package without a pinned version, or one inside a Docker image, is not checked.
- Skills: RosmarOps lists their files but does not read their settings yet (for example `allowed-tools`). GitHub Copilot's skills are not attributed yet.
- The first run of this version is not comparable with the last one, because the detection rules changed.
- macOS preview: it does not check scheduled tasks (launchd), antivirus exclusions, shell startup files or Python packages against the threat data; it has no weekly review; the report is in English unless you run it with `--lang`.
- The limits of v0.4.0 still apply.

See `docs/trust-model.md` for every claim and how to check it.
