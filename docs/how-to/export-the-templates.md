# How to export the templates

The open repository `qtorb/rosmarops-templates` holds the same templates RosmarOps offers in «Choose a template», so people and their agents can use them without running RosmarOps. They are never written by hand: they come from the program, so what the repository says is what RosmarOps does.

## What is exported

`go run ./tools/exporttemplates -version X.Y.Z -out <folder of the templates repository>` writes:

- `templates/<agent>/<use>/<file>`: the text the report copies for that template, unchanged. Today:
  - `claude-code/{read-only,local-development,sandboxed-development}/settings.json` and `claude-code/unattended/command.txt`;
  - `cursor/{read-only,local-development}/sandbox.json`;
  - `grok-build/{read-only,local-development,sandboxed-development}/config.toml` and `grok-build/unattended/command.txt`.
- `templates/<agent>/<use>/README.md`: the template's name, the steps or the sentence the report shows with it, its rows («Does on its own», «Asks you», «Doesn't do», «Doesn't cover»), all the catalog's English texts, and the line «Generated by RosmarOps X.Y.Z. Do not edit by hand.». Where the report shows a different «Doesn't cover» on each system (Claude Code's «Local development»), the README gives both, after «Windows:» and «macOS and Linux:». The link to rosmarops.com is in the repository's own README, not in each template.
- `skills/rosmarops-templates/SKILL.md`: the Claude Code skill that applies a template, from `tools/exporttemplates/SKILL.md`.

The launch commands (`command.txt`) have the task placeholder `<task>`, as the English report shows it: the placeholder is text for the person and follows the report's language (`<tarea>` in Spanish, `profiles.Placeholder`); nothing in RosmarOps substitutes it.

The export replaces the whole `templates/` folder, so a template RosmarOps no longer offers disappears from the repository. Grok Bot's templates copy no text, so they have no folder.

The blocks are constants of `internal/profiles` and the texts are the catalog's: nothing comes from the computer that runs the export, and two runs give the same bytes.

## Where it comes from

- `internal/report/templates_export.go` (`ExportTemplates`) lists the templates from the same data the report draws: `profiles.Block` and `profileRows` for Claude Code, `profiles.GuidedBlock` and `guidedAgents` for Cursor and Grok Build.
- `TestExportTemplates_SameAsTheReport` checks that every exported file is exactly what the report copies after its sentence, and that every template the report offers is exported. `TestExportTemplates_NothingFromTheComputer` checks that no home, user, host, working or temporary folder appears.

## When you change a template

Change it in `internal/profiles` (and its rows or texts in the report and the catalog) as usual. The export follows on its own; the tests fail if the report and the export differ. A new agent with templates needs its file name in `exportTemplates`; a new template needs its folder name in `templateUse`.

## Publishing a version

`release.yml` does not export the templates: opening a pull request in another repository from the workflow would need a new credential, and the owner decided against one. After each release, the person who maintains the templates (today, the builder) opens the pull request by hand:

1. Check out the released tag and the templates repository side by side:

   ```
   git -C rosmarops checkout vX.Y.Z
   git clone https://github.com/qtorb/rosmarops-templates
   git -C rosmarops-templates checkout -b export-X.Y.Z
   ```

2. Export from the tag into the templates repository:

   ```
   cd rosmarops
   go run ./tools/exporttemplates -version X.Y.Z -out ../rosmarops-templates
   ```

   It replaces `templates/` and writes `skills/rosmarops-templates/SKILL.md`; it does not touch the repository's own `README.md` or any other file.
3. Look at the difference (`git -C ../rosmarops-templates diff --stat`). With no template change since the last version, only the «Generated by RosmarOps» line of each README changes.
4. Commit, push the branch and open the pull request in `qtorb/rosmarops-templates`, titled «Templates from RosmarOps X.Y.Z». The owner merges it.

Export only from a released tag, never from `master`: the line «Generated by RosmarOps X.Y.Z» must name a version people can download.

## The skill

`tools/exporttemplates/SKILL.md` is the skill's text as signed (BV-266 §2, with steps 2 and 5 as the advisor set them on 20-11): the templates go in the person's user settings (`~/.claude/settings.json`), the skill says so before showing the change, writes only after a yes, and never changes managed settings. Change it only with a new signature.
