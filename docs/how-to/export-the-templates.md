# How to export the templates

The open repository `qtorb/rosmarops-templates` holds the same templates RosmarOps offers in «Choose a template», so people and their agents can use them without running RosmarOps. They are never written by hand: they come from the program, so what the repository says is what RosmarOps does.

## What is exported

`go run ./tools/exporttemplates -version X.Y.Z -out <folder of the templates repository>` writes:

- `templates/<agent>/<use>/<file>`: the text the report copies for that template, unchanged. Today:
  - `claude-code/{read-only,local-development,sandboxed-development}/settings.json` and `claude-code/unattended/command.txt`;
  - `cursor/{read-only,local-development}/sandbox.json`;
  - `grok-build/{read-only,local-development,sandboxed-development}/config.toml` and `grok-build/unattended/command.txt`.
- `templates/<agent>/<use>/README.md`: the template's name, the steps or the sentence the report shows with it, its rows («Does on its own», «Asks you», «Doesn't do», «Doesn't cover»), all the catalog's English texts, and the line «Generated by RosmarOps X.Y.Z. Do not edit by hand.».
- `skills/rosmarops-templates/SKILL.md`: the Claude Code skill that applies a template to a project, from `tools/exporttemplates/SKILL.md`.

The export replaces the whole `templates/` folder, so a template RosmarOps no longer offers disappears from the repository. Grok Bot's templates copy no text, so they have no folder.

The blocks are constants of `internal/profiles` and the texts are the catalog's: nothing comes from the computer that runs the export, and two runs give the same bytes.

## Where it comes from

- `internal/report/templates_export.go` (`ExportTemplates`) lists the templates from the same data the report draws: `profiles.Block` and `profileRows` for Claude Code, `profiles.GuidedBlock` and `guidedAgents` for Cursor and Grok Build.
- `TestExportTemplates_SameAsTheReport` checks that every exported file is exactly what the report copies after its sentence, and that every template the report offers is exported. `TestExportTemplates_NothingFromTheComputer` checks that no home, user, host, working or temporary folder appears.

## When you change a template

Change it in `internal/profiles` (and its rows or texts in the report and the catalog) as usual. The export follows on its own; the tests fail if the report and the export differ. A new agent with templates needs its file name in `exportTemplates`; a new template needs its folder name in `templateUse`.

## Publishing

Exporting at release time into the templates repository is not automatic yet: it needs a way for `release.yml` to open a pull request in another repository, which is a decision of the owner. Until then, run the tool by hand on the released tag and open the pull request in `qtorb/rosmarops-templates`.
